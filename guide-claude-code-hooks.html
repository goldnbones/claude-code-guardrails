Why hooks, not just prompts

Claude Code decides which shell commands to run. You can ask it in CLAUDE.md to be careful, and it usually is. But "usually" is not a safety guarantee, and the failure mode is expensive: a wrong path in an rm -rf, a git push --force to main, a git reset --hard over uncommitted work. A prompt is advice. A hook is enforcement: it runs before the tool call and can refuse it outright.

The hook contract

Claude Code fires a PreToolUse hook right before it executes a tool. The hook is any command. It receives a JSON object on stdin:

{
  "session_id": "…",
  "tool_name": "Bash",
  "tool_input": { "command": "rm -rf ./build" }
}

The exit code is the decision:

  • Exit 0 — allow the tool call.
  • Exit 2 — block it. Whatever the hook writes to stderr is shown to Claude, so it can read the reason and adapt.

That is the whole mechanism. A safety hook is just a program that reads the command, decides, and sets its exit code.

Blocking destructive commands

Here is a minimal, dependency-free guard-destructive.py. It blocks the commands that most often cause real damage:

#!/usr/bin/env python3
import json, re, sys

RULES = [
    (r"\brm\s+(-\w+\s+)*-\w*[rf]\w*\s+(-\w+\s+)*(/|~|\$HOME|\*)(\s|$)",
     "recursive rm targeting root, home, or a wildcard"),
    (r"git\s+push\s+.*(--force|-f)\b(?!-with-lease)",
     "force-push (use --force-with-lease instead)"),
    (r"git\s+reset\s+--hard|git\s+clean\s+-\w*f",
     "git reset --hard / git clean -f wipes uncommitted work"),
    (r"drop\s+(table|database)|truncate\s+table",
     "destructive SQL"),
    (r"(curl|wget)\s+[^|]*\|\s*(sudo\s+)?(ba)?sh",
     "piping a downloaded script straight into a shell"),
]

def main():
    try:
        data = json.load(sys.stdin)
    except Exception:
        sys.exit(0)                      # fail open on malformed input
    cmd = (data.get("tool_input") or {}).get("command", "")
    for rx, why in RULES:
        if re.search(rx, cmd, re.I):
            sys.stderr.write(f"BLOCKED: {why}\n  command: {cmd[:200]}\n")
            sys.exit(2)                  # 2 = block, stderr shown to Claude
    sys.exit(0)

if __name__ == "__main__":
    main()

Save it to .claude/hooks/guard-destructive.py and make it executable with chmod +x.

Wiring it in settings.json

Register the hook for the Bash tool in .claude/settings.json:

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          { "type": "command",
            "command": "python3 \"$CLAUDE_PROJECT_DIR\"/.claude/hooks/guard-destructive.py" }
        ]
      }
    ]
  }
}

Restart Claude Code, ask it to run rm -rf /tmp/x /, and watch it get refused with the reason. The matcher is a regex against the tool name, so "Edit|Write" would target file edits instead.

Blocking secret leaks

The same pattern guards file writes. A PreToolUse hook on Edit|Write can refuse to write anything that looks like a live credential:

PATTERNS = [
    (r"AKIA[0-9A-Z]{16}", "AWS access key id"),
    (r"-----BEGIN[ A-Z]*PRIVATE KEY-----", "private key block"),
    (r"sk-[A-Za-z0-9]{20,}", "OpenAI-style secret key"),
    (r"ghp_[A-Za-z0-9]{30,}", "GitHub token"),
]

Read tool_input.content (for Write) or tool_input.new_string (for Edit), match against the patterns, and exit 2 on a hit. Now a hard-coded key never lands in a tracked file in the first place.

The edge cases a naive version misses

The regex above is a good start, but a determined command slips past a single pattern. Real shells do things the naive version does not see:

  • Chained commands: cd /tmp && rm -rf ~ or a; rm -rf /; b — the dangerous part is buried in the middle.
  • Pipes and subshells: echo x | (rm -rf /), $(rm -rf ~), backticks.
  • Wrappers: sudo -E rm -rf /, env X=1 rm …, xargs rm, bash -c "rm -rf /".
  • Quoting tricks that break a simple word match.

Handling these means actually splitting the command on shell operators, unwrapping subshells and known wrappers, and resolving paths, rather than matching one line. That is the difference between a demo and something you trust on a real repo.
